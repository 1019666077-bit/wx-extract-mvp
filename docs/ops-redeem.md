## 发码

1. 在仓库根目录本地生成（**不要把输出 commit 进仓库**）：
   ```bash
   python3 scripts/gen-codes.py --monthly 1 --quarterly 0
   ```
   或 `--quarterly 1`。脚本打印 JSON；月付格式 `LLE-M-XXXXXX`，季卡 `LLE-Q-XXXXXX`。
2. **只在微信私聊**把那一条码发给该用户。不要发朋友圈、小红书、群公告、公开评论，也不要写进 `data/codes.json`。
3. 提醒用户：打开开通页，把码粘进「兑换码」后点解锁。公开 Pages 上的 `codes.json` 是空数组；浏览器在白名单为空时按格式接受 `LLE-M` / `LLE-Q` 码。
4. 在你自己的表格里记下已发（见下一节）。
5. 合并前跑 `bash scripts/check-codes-json.sh`：公开仓 `codes.length > 0` 会失败。

已付款未兑、或上线到期功能后旧 unlock 失效的用户：用新生成的**未进仓**单码私聊补发。

## 码用尽后如何补货

继续本地跑生成脚本，私聊发放。**禁止**把条目追加进 `data/codes.json` 再部署 GitHub Pages。

生成用 Python `secrets` 模块，后缀为 6 位大写字母+数字，前缀固定为 `LLE-M` / `LLE-Q`。

## 安全说明（诚实限制）

这是 MVP，**不是安全实现**：

- 公开仓不再存放可用码库存；空白名单时任意符合格式的码都能在本机兑开（知道格式的人仍可自造码）
- 能看源码的人仍可改 `localStorage` 或绕过前端锁直接打开课页
- 前端锁只能挡住不想翻代码的普通用户
- 没有核销、没有「一码一用」服务端记录；同一码可被多人使用
- 月付/季卡到期只看本机 `expiresAt`；退出解锁只清本机 `localStorage`
- 上线本规则前没有 `expiresAt` 的旧解锁状态视为已过期，需重新兑码

后续若要上真支付（微信官方收款、一单一码、服务端核销），另开方案，不要在本静态站硬接支付 API。
